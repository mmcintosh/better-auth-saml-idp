# Schema

[Guide](README.md) › Schema

The plugin adds up to three tables. Only the first is always needed; the others exist only when their feature is enabled, so D1 hosts with `validateSchema` never need tables they don't use.

Create them with Better Auth's CLI, like any plugin's tables:

```bash
npx auth migrate     # Kysely adapters: create the tables
npx auth generate    # Drizzle/Prisma: write the schema, then run your own migration
```

On Cloudflare D1 with Drizzle, the example has ready-made migrations: [`examples/workers-hono/migrations/`](../../examples/workers-hono/migrations/) (`0001` core, `0002` replay key, `0003` registry, `0004` Single Logout).

Rename tables or columns with the [`schema` option](options.md#schema).

## `samlIdpSeenRequest` (always)

Replay protection ([ADDENDUM-01 R2](../../DECISIONS.md)): one row per (SP, AuthnRequest ID) seen, and per LogoutRequest ID.

| Field | Type | Key | Description |
|---|---|---|---|
| `id` | string | primary | Row id, generated by Better Auth. |
| `key` | string | **unique** | `sha256(spId, requestId)`. A replay is detected by the INSERT failing on this constraint, so it holds across instances and under concurrency. |
| `spId` | string | | The SP's `id`. |
| `requestId` | string | | The AuthnRequest's `ID` (LogoutRequests are namespaced `logout:`). |
| `expiresAt` | date | index | End of the replay window (request age limit plus clock skew). Swept automatically. |

<details><summary>Hand-written Drizzle (SQLite/D1)</summary>

```ts
export const samlIdpSeenRequests = sqliteTable(
  "saml_idp_seen_requests",
  {
    id: text("id").primaryKey(),
    key: text("key").notNull().unique(),
    spId: text("sp_id").notNull(),
    requestId: text("request_id").notNull(),
    expiresAt: integer("expires_at", { mode: "timestamp_ms" }).notNull(),
  },
  (t) => [index("saml_idp_seen_requests_expires_idx").on(t.expiresAt)],
);
```
</details>

**Replay protection needs a database that enforces UNIQUE.** Every real database does; Better Auth's in-memory adapter doesn't (development only).

## `samlIdpServiceProvider` (with `registry.enabled`)

SPs stored at runtime. See [Registry](service-providers.md#registry).

| Field | Type | Key | Description |
|---|---|---|---|
| `id` | string | primary | Row id. |
| `spId` | string | **unique** | The SP's `id` (copied out of `config` for lookups). |
| `entityId` | string | **unique** | The SP's entity ID (copied out of `config`). |
| `config` | string | | The SP's options as JSON. Validated on every write and on every (uncached) read; a row that no longer validates is ignored and logged. |
| `enabled` | boolean | | Disabled SPs are treated as unknown. |
| `createdAt` | date | | |
| `updatedAt` | date | | |
| `updatedBy` | string | | The user id of the last change (optional). |

<details><summary>Hand-written Drizzle (SQLite/D1)</summary>

```ts
export const samlIdpServiceProviders = sqliteTable("saml_idp_service_providers", {
  id: text("id").primaryKey(),
  spId: text("sp_id").notNull().unique(),
  entityId: text("entity_id").notNull().unique(),
  config: text("config").notNull(),
  enabled: integer("enabled", { mode: "boolean" }).notNull(),
  createdAt: integer("created_at", { mode: "timestamp_ms" }).notNull(),
  updatedAt: integer("updated_at", { mode: "timestamp_ms" }).notNull(),
  updatedBy: text("updated_by"),
});
```
</details>

## `samlIdpSessionParticipant` (with `singleLogout.enabled`)

Which SPs received an assertion in which session, so logout can reach them all. See [Single Logout](single-logout.md).

| Field | Type | Key | Description |
|---|---|---|---|
| `id` | string | primary | Row id. |
| `key` | string | **unique** | `sha256(sessionKey, spId)`: one row per SP per session. |
| `sessionKey` | string | index | A hash of the Better Auth session id (never the id or token itself). |
| `spId` | string | | The SP's `id`. |
| `nameId` | string | | The NameID this SP was given (refreshed on each assertion; transient NameIDs change). |
| `nameIdFormat` | string | | Its format. |
| `sessionIndex` | string | | The SessionIndex this SP was given: a keyed MAC over (session, SP), different for every SP. |
| `expiresAt` | date | index | Follows the session's expiry, including Better Auth's sliding refresh. Swept automatically. |

<details><summary>Hand-written Drizzle (SQLite/D1)</summary>

```ts
export const samlIdpSessionParticipants = sqliteTable(
  "saml_idp_session_participants",
  {
    id: text("id").primaryKey(),
    key: text("key").notNull().unique(),
    sessionKey: text("session_key").notNull(),
    spId: text("sp_id").notNull(),
    nameId: text("name_id").notNull(),
    nameIdFormat: text("name_id_format").notNull(),
    sessionIndex: text("session_index").notNull(),
    expiresAt: integer("expires_at", { mode: "timestamp_ms" }).notNull(),
  },
  (t) => [index("saml_idp_session_participants_session_idx").on(t.sessionKey), index("saml_idp_session_participants_expires_idx").on(t.expiresAt)],
);
```
</details>

## Other storage

- **`verification`** (Better Auth's table): pending sign-in requests (`resume` links), POST-binding continuations, and logout state. All are single-use (consumed atomically) and short-lived. With secondary storage such as KV configured, set `verification: { storeInDatabase: true }` so single-use consumption stays atomic.
- Expired rows of all of these are swept automatically, at most once a minute per isolate, when SAML requests arrive. On a very quiet IdP you can also delete rows with `expires_at < now` from a cron.
